手冊、驗收、交接、防呆全要有？搭出能上班的完整 Harness

> 系統不用一次搭好，先讓輪子轉起來，再補上擋風玻璃。

## 為什麼要學這個？

你已經有了工作手冊、驗收卡、交接卡、防呆條件與分層規則。它們各自活在不同的文
件夾裡，像一套工具組。但每次要開始工作，你還是得一個個打開、複製、貼上、對照
。效率沒變快，只是整理得比較整齊。

你真正需要的是把零件串成機台。不是每樣都要加，而是讓核心輪子先轉動，再依需求
補上零件。就像搭積木，先放底板，再依高度往上疊，不用一次把整套城堡拼完，也能
先蓋出一間能住人的屋。

## 核心概念

### 問題：零件很多，但不會轉動

零件獨立存在時，無法自動協作。你把規則寫得很好，但沒有設定觸發順序與載入時機
。AI 不知道該先讀手冊、再照驗收卡檢查，或是該何時切換情境。工作流斷裂，產出
品質就靠運氣。

解法是用「時序邏輯」把零件串起來。不是同時丟所有檔案，而是依工作階段分步載入
。先載入交接卡確立背景，再載入全域手冊設定底線，接著依任務載入情境插件，最後
貼上驗收卡與防呆條件。按順序來，AI 不會亂跑，你也不會漏檢。

### 問題：想一次到位，系統反而卡住

很多人嘗試第一版就塞滿所有設定。手冊要長、驗收要細、防呆要多、情境要全。結果
 AI 回應變慢、格式混亂、關鍵條件互相覆蓋。你想建跑車，但引擎還沒啟動就想裝空
調與衛星導航。

解法是用最小可用系統思維。第一版只綁三件事：全域手冊、任務輸出格式、驗收清單
。跑順了再加交接卡、情境切換與防呆條件。系統是滾動更新的，不是蓋好就封檔。每
次迭代只加一個零件，確認不卡頓再繼續疊。

### 問題：工作流斷層，切換任務就失準

不同任務的底線與流程不同。企劃需要嚴謹結構，社群需要彈性語氣，客服需要快速回
覆。如果你用同一套組合打天下，AI 會在高規矩與高彈性之間搖擺。

解法是按任務類型配置工作流模板。高風險任務（報價、對外公告、合規文件）走完整
鏈：交接背景 → 全域底線 → 情境格式 → 防呆條件 → 驗收檢查。低風險任務（腦
力激盪、內部草稿、資料整理）走縮減鏈：任務描述 → 全域底線 → 驗收清單。依風
險階級切換串接深度，不浪費資源，也不放過關鍵檢查。

### 問題：規則寫完就停手，越用越偏

工作流不是寫完就結束，而是持續對齊實際產出。你發現某些情境產出不準，通常是因
為沒更新個人引導卡，或情境檔案裡漏了關鍵欄位。不追蹤、不修正，系統會慢慢變質
。

解法是在每份情境檔末尾留一欄「迭代紀錄」。每次產出完花兩分鐘對照驗收卡，發現
遺漏就補進對應層級。全規則動全域檔，情境動情境檔，個人習慣動引導卡。維持系統
乾淨，不堆積廢規則。

## 動手做

選一個你最近常做的真實任務（例如：社群貼文產出、競品分析、客戶問答回覆），照
以下步驟組裝你的完整 Harness。

**第一步：選任務與風險階級**
判斷該任務的風險高低。對外、涉資、涉法、涉品牌，一律歸為高風險。內部草稿、資
料整理、腦力激盪歸為低風險。

**第二步：組裝高風險工作流（依序載入）**
1. 開頭貼「交接卡」：任務背景、受眾、關鍵限制、前次遺漏點。
2. 載入「全域手冊」：語氣、語言、禁止事項、核心原則。
3. 貼上「情境插件」：該任務專屬結構與格式要求。
4. 貼上「防呆條件」：高風險必查項（數字核對、來源註記、主管確認提示等）。
5. 結尾貼「驗收卡」：對照清單，要求 AI 先自我檢查再回覆。

**第三步：組裝低風險工作流（精簡版）**
1. 貼「全域手冊」
2. 貼「任務描述」
3. 結尾貼「驗收卡（簡版）」
4. 任務結束後清空個人引導卡

**產出物檢查清單**
- [ ] 明確區分高/低風險任務串接深度
- [ ] 工作流依序不跳步，無同時載入衝突
- [ ] 驗收卡與防呆條件互為對照，不重複列點
- [ ] 留有一欄迭代紀錄，可快速回補遺漏規則

## 這堂課的收穫

- 能將單一任務轉為標準化工作流，依風險階級切換串接深度
- 掌握「交接→底線→情境→防呆→驗收」的無縫串接順序
- 產出可直接套用的個人化 Harness 模板包，含高/低風險雙軌版本

## 小抄

| 階段 | 載入檔案 | 目的 | 注意事項 |
|------|----------|------|----------|
| 開場 | 交接卡 + 全域手冊 | 確立背景與絕對底線 | 不混入格式細節 |
| 執行 | 情境插件 | 提供結構與輸出規範 | 每次任務僅載入相對應情境 |
| 攔截 | 防呆條件 | 攔截高風險輸出 | 僅高風險任務啟用 |
| 收尾 | 驗收卡 | 自我檢查與修正 | 要求 AI 先列檢查結果再給最終版 |
| 維護 | 迭代紀錄 | 滾動更新規則 | 動哪層補哪層，不覆蓋其他檔案 |
